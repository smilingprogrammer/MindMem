MindMem Current Architecture

Implemented flow: input, sensory processing, short-term memory, and initial long-term consolidation

Data Flow

  • 1. Validate raw text and create an event.
  • 2. Score relevance with heuristics.
  • 3. Use the LLM only when relevance is unclear.
  • 4. Extract and store only relevant content.
  • 5. Group the record and update working state.
  • 6. Retrieve focused context for the agent.
  • 7. Manually consolidate a selected topic.
  • 8. Preserve episodes and version durable memories.

Troubleshooting Map

  • Bad IDs or empty text: input/text.py
  • Wrong relevance: lightweight_relevance.py or llm_relevance.py
  • Bad entities/facts: llm_extraction.py
  • Missing/reordered records: memory/short_term.py
  • Wrong grouping: memory/topics.py
  • Wrong task/state data: memory/reasoning_state.py
  • Wrong agent context: memory/retrieval.py
  • Wrong candidates: memory/consolidation.py
  • Wrong history/dedup: memory/long_term.py

LLM Boundary

  • Relevance LLM returns a score, not a label.
  • Python derives the label at 0.40.
  • Extraction is one structured LLM call.
  • Input and output use JSON Schema.

Current Runtime Behavior

  • Short-term records live only in process RAM.
  • Sessions are separated by user and session IDs.
  • Related records share a topic; 3 topics stay active.
  • Explicit decisions, tasks, and tool results are tracked.
  • Focused context retrieval makes no LLM call.
  • Consolidation is manual, rule-based, and idempotent.
  • Long-term episodes and memories currently live in RAM.
  • Oldest record is removed after capacity is reached.
  • No database or persistence adapter is active.
